App bootstrap src/app

Suggested additions
plugin-manager.tsExtension host that loads browser add-ons at startup, decoupled from app-shell so core can boot without plugins present.
crash-reporter.tsCaptures unhandled errors and renderer crashes, writes a minidump before the process exits — essential for post-mortem debugging.

Suggested additions
devtools-panel.tsInspector UI exposing the live DOM tree, network log, and JS console. Best modelled as a first-class UI component rather than a bolt-on afterthought.
command-palette.tsKeyboard-driven omnibox for settings, history, and extensions. Keeps the browser accessible without deep menu hierarchies.

Navigation src/browser/navigation
url-parser.ts navigation-controller.ts prefetch-manager.ts history-predictor.ts
Suggested additions
prefetch-manager.tsSpeculatively fetches URLs from hovered links or typed prefixes, feeding request-manager before the user commits to navigating.
history-predictor.tsUses visit frequency + recency to rank autocomplete candidates in the address bar — bridges navigation-controller and the storage layer.
Phase 2 · fetch documents
Networking src/browser/networking
request-manager.ts http-cache.ts websocket-manager.ts
Suggested additions
http-cache.tsIntercepts responses before the renderer and writes them to disk keyed by URL + Vary headers. Dramatically reduces repeat-load latency — belongs here, not in storage.
websocket-manager.tsManages persistent socket connections separate from HTTP. Needed by modern web apps and belongs in the networking tier, not buried in the JS runtime.

Phase 3 · parse and display HTML/CSS
Rendering pipeline src/browser/rendering
html-parser.ts css-parser.ts dom-tree.ts layout-engine.ts paint-engine.ts accessibility-tree.ts compositor.ts
Suggested additions
accessibility-tree.tsBuilds a parallel AX tree from the DOM, exposing ARIA roles and labels to platform accessibility APIs. Best added right after dom-tree.ts is stable.
compositor.tsGPU layer compositing pass after paint-engine. Promotes promoted layers to textures for smooth scrolling and CSS transforms without a full repaint on every frame.
▼
Phase 4 · script execution
JavaScript execution src/browser/javascript
js-runtime-bridge.ts dom-bindings.ts event-loop.ts web-workers.ts wasm-bridge.ts
Suggested additions
web-workers.tsRuns JS in isolated off-main-thread contexts. Critical for non-blocking CPU work — shares the runtime bridge but has a separate message channel from the main event-loop.
wasm-bridge.tsInstantiates and links WebAssembly modules into the JS context. Increasingly required by modern web apps; a runtime concern, not a fetch concern, so it lives here.

Phase 5 · persistence and safety
State and safety src/browser / storage · security · tabs
storage/ security/ tabs/ downloads/ bookmarks/ history/ csp-enforcer.ts extension-api.ts
Suggested additions
csp-enforcer.tsParses Content-Security-Policy headers and blocks inline scripts, mixed content, and unauthorized resource origins. Distinct from the cert/permission checks already in security/.
extension-api.tsPublic surface for plugin-manager to give add-ons controlled access to tabs, storage, and network events without reaching into core internals directly.
